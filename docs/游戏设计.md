# 游戏设计（v2.0）

> 适用于 Word Planet 第二版：星球地图 + 关卡玩法 + 三层奖励 + 徽记兑换。
> 本文只定义**规则与数值**，不含实现细节；实现见 `Agent实现说明书.md`。
> 所有规则已与产品方逐条确认（见文末「决策记录」）。
> v2.0 相对 v1.0：代币体系从「三色单层」改为「花 → 星 → 徽记」三层，解锁条件改为按徽记数量判定。

---

## 1. 核心循环

```
地图选星球
  → 关卡过场（1.2s「第 8 关 · 基础问候词」）
  → 15 题（每题一个玩法）
  → 即时反馈：答对得小红花 / 答错进错题本
  → 结算：本次表现 + 本套存档 + 手动兑换
  → 回地图（该星球进度 +1 套）
  → 错题补花（长期，补齐才能满套）
  → 手动兑换：3 花 → 1 星；5 星 → 1 徽记
```

**目标时长**：一关 3–5 分钟（15 题 × 12–20 秒）。

---

## 2. 三层奖励

```
答对 1 题 → 1 朵小红花
3 朵小红花 → 1 颗星星
5 颗星星   → 1 个徽记（该星球专属）
```

| 层 | 单位 | 换算 | 一套 15 题的上限 |
|---|---|---|---|
| 第一层 | 🌸 小红花 | 答对 1 题 = 1 朵 | 15 朵 |
| 第二层 | ⭐ 星星 | 3 朵 = 1 颗 | 5 颗 |
| 第三层 | 徽记 | 5 颗 = 1 个 | 1 个 |

**关键约束：**

1. **全程手动兑换**，不自动变。点一次兑一个，允许连点。
2. 兑换会消耗下层：兑星后花减少，兑徽记后星减少。
3. 一套 15 题全对 = 15 朵花 = 5 颗星 = **1 个徽记**。
4. 答错一题就少一朵花；**必须把该套所有错题的花补齐**，才能凑满 15 朵拿到这 1 个徽记。
5. 每套最多产出 1 个徽记；重练同一套不再产出。

---

## 3. 两颗纯练星球

| 星球 | 等级 | 题型 | 奖励 | 显示 |
|---|---|---|---|---|
| 字母表 | L1 | letter | **无** | 只有「已完成 / 未完成」 |
| 听力理解 | L3 | listening | **无** | 只有「已完成 / 未完成」 |

**规则：**

- 不产小红花、不产星星、不产徽记。
- 界面上**不显示任何计数**，只显示完成状态。
- 「完成」的判定与「拿小红花」一致：**15 题全部答对**才算完成。
- 答错的题同样进错题本，连对 3 次补回；补回的那题也计入完成条件。
- **但完成状态要写入数据库**（`set_progress.is_complete`），因为解锁 L2 需要「字母表已完成」。

## 4. 徽记与星球对应

| 星球 | 等级 | 题型 | 徽记 | 套数（=徽记上限） | 产奖励 |
|---|---|---|---|---|---|
| 字母表 | L1 | letter | — | 1 | ❌ 纯练 |
| 基础问候词 | L1 | word | 🥚 破壳蛋 | 22 | ✅ |
| 常用单词 | L2 | word | 🐻 小熊 | 32 | ✅ |
| 简单拼写 | L2 | spelling | ✍️ 羽毛笔 | 27 | ✅ |
| 单词跟读 | L2 | pronunciation | 🐦 唱歌小鸟 | 29 | ✅ |
| 听力理解 | L3 | listening | — | 1 | ❌ 纯练 |
| 拼写进阶 | L3 | spelling | 🔮 水晶球 | 95 | ✅ |

**视觉规格：**

- 🥚 破壳蛋、🐻 小熊、🔮 水晶球：SVG 自绘（卡通扁平 + 粗描边）
- ✍️ 羽毛笔：直接用 emoji
- 🐦 唱歌小鸟：**直接用产品方提供的蓝鸟图片**，已抠白底、裁掉文字、统一为 256×256 透明 PNG，
  文件在 `frontend/src/assets/bird.png`，组件里 `import birdUrl from '../assets/bird.png'` 使用

**徽记上限 = 该星球的套数。** 每套满星产 1 个徽记，该星球全部套做完即徽记拿满。

## 5. 错题与补花

| 项 | 规则 |
|---|---|
| 主流程答错 | 0 朵花，题进错题本 |
| 补花条件 | 错题本里**连续答对 3 次**（`MASTERY_STREAK` 由 2 改 3）→ 补发该题 1 朵花，同时移出错题本 |
| 每题一次 | 同一题只补一次，重复练习不再给（`question_flowers` 唯一约束） |
| 跟读题 | 相似度 ≥2 星给花；≤1 星进错题本；错题本里给「🔁 跟读补花」入口，重读 ≥2 星补花 |
| 满套条件 | 该套 15 题**全部拿到过花**（不看当前余额，看累计产出） |
| 未来扩展 | 可能给「连对 3 次」加时限，防止抢记后连点（**本期不做**） |

## 6. 解锁条件

### 6.1 解锁 L2

```
字母表「已完成」  +  基础问候词 3 个 🥚 破壳蛋
```

- 字母表只有 1 套，做完（15 题全对）即算完成，**不产徽记**。
- 基础问候词要 3 套满星 = 3 个破壳蛋。
- 合计真实工作量：**字母表 1 套 + 基础问候词 3 套 = 4 套**。

### 6.2 解锁 L3

```
常用单词 3 个 🐻  +  简单拼写 2 个 ✍️  +  单词跟读 2 个 🐦
```

- 每颗星球**分别达到自己的数量**，不是合计 7 个任意凑。
- 合计真实工作量：**3 + 2 + 2 = 7 套**（每套都要满星）。

### 6.3 通用规则

| 项 | 规则 |
|---|---|
| 形式 | 攒够后解锁「能力测试」入口 |
| 能力测试 | 10 题，对 8 题通过 |
| 通过后 | 解锁 `max_level`，由用户选择升级或留级 |
| L3 | 终点，无下一级 |
| 听力理解 | 纯练，**不参与任何解锁条件** |
| 等级回访 | 高等级可随时回低等级，进度保留 |

| 项 | 取值 | 说明 |

| 重练 | 允许 | 花/星/徽记都不变（以第一次为准） |

## 8. 四个玩法

### 8.1 拖卡喂星球（letter / word）

| 项 | 规则 |
|---|---|
| 画面 | 题干在上；中央呼吸星球；下方 4 张卡 |
| 操作 | 桌面拖拽入星球；手机点卡片飞入 |
| 答对 | 星球吞卡 + 花 +1 动画 + `ding` |
| 答错 | 卡片弹回 + 摇头抖动 + `buzz` + 进义项面板 +「下一题」 |
| 边界 | 提交后禁用；长词组两行；360px 竖排 |

### 8.2 字母砖拼词（spelling）

| 项 | 规则 |
|---|---|
| 画面 | 释义在上；拼写槽；下方字母砖 |
| 砖数 | `len≤4` → len+4；`5–7` → len+5；`8+` → len+6（上限 18） |
| 干扰字母 | 从同套其它单词取样 |
| 重复字母 | 按答案字母计数生成（banana = 3×a、2×n） |
| 提交 | 槽满后出现「✓ 就这样」，**由孩子确认**，不自动提交 |
| 答对 | 槽变绿 + 逐字弹跳 + 花 +1 |
| 答错 | 槽变红抖动 + 显示正确拼写 + 义项 |
| 备选 | 保留键盘输入按钮 |

### 8.3 听音找词（listening）

| 项 | 规则 |
|---|---|
| 画面 | 大唱片按钮 + 4 张卡 |
| 播放 | 进题自动播 1 次，可重听 1 次（共 2 次机会） |
| 答对/答错 | 同 8.1（但本星球不产花） |
| 降级 | 不支持 `SpeechSynthesis` → 显示题干文字当选择题 |

### 8.4 麦克风跟读（pronunciation）

| 项 | 规则 |
|---|---|
| 画面 | 单词大字 + 麦克风 + 实时音量条 |
| 操作 | 按住说话，松开识别 |
| 判定 | 编辑距离 ≤1（现有前端逻辑） |
| 相似度反馈 | **实时显示 1–3 星**，让孩子知道读得怎样 |
| ≥2 星 | 得 1 朵花（不因相似度高低给多朵） |
| ≤1 星 | 0 朵花，进错题本 |
| 空识别 | 允许重试 2 次，不惩罚 |
| 不可用时 | 听标准音后点「我读过了」，计为 ≥2 星，得花 |

### 布局要求（v2.0 修正）

- 保持 **L1 → L2 → L3 自下而上**的爬升顺序，7 颗星球顺序不变。

## 12. 反馈系统

**音效**（Web Audio 合成，无音频文件）：`ding`（答对）、`buzz`（答错）、`pop`（入槽）、`tick`（字母砖）、`whoosh`（过场）、`star`（结算，逐颗升调）、`medal`（兑换徽记）。

**动画**（纯 CSS）：星球呼吸、卡片飞行、花弹出、答错抖动、连击跳字、结算逐颗亮、兑换时花飞向星。全部尊重 `prefers-reduced-motion`。

项目统一「一天一清算」，按 `Asia/Shanghai`。

### 14.1 数据模型（建议实现，表名可改但语义必须保留）

**新表 `question_flowers`** —— 花账本，唯一真相

```sql
CREATE TABLE question_flowers (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  question_id UUID NOT NULL REFERENCES questions(id),
  set_no INT NOT NULL,                     -- 冗余存，便于按套汇总
  source VARCHAR(16) NOT NULL,             -- 'main' | 'practice'
  earned_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (user_id, question_id)            -- 每题只能拿一次，防刷
);
```

为什么必须按题记，而不是只在这一套上存一个数字：
- 判「满套」= 该套 15 题是否都在此表里，天然防重复；
- 错题补花有据可查；
- 兑换星星只扣「可兑花数」，不影响「已获得花数」。

**`set_progress` 加 4 列** —— 按套缓存，避免每次求和

```sql
ALTER TABLE set_progress
  ADD COLUMN flowers_earned  INT     NOT NULL DEFAULT 0,  -- 0-15，只增不减
  ADD COLUMN stars_earned    INT     NOT NULL DEFAULT 0,  -- 0-5，已兑星数
  ADD COLUMN medals_granted  INT     NOT NULL DEFAULT 0,  -- 0/1，是否已产徽记
  ADD COLUMN is_complete     BOOLEAN NOT NULL DEFAULT FALSE;  -- 纯练星球也用此列
```

口径：
- `flowers_earned` = `question_flowers` 里属于该套的行数（每次变化时重算写回）
- 可兑星数 = `(flowers_earned - stars_earned * 3) // 3`
- 可兑徽记 = `stars_earned - medals_granted * 5 >= 5`
- 纯练星球：`flowers_earned` 恒为 0，只有 `is_complete`

**新表 `planet_medals`** —— 按星球累计徽记

```sql
CREATE TABLE planet_medals (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  knowledge_point_id UUID NOT NULL REFERENCES knowledge_points(id),
  medals INT NOT NULL DEFAULT 0,
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (user_id, knowledge_point_id)
);
```

用途：地图徽标计数；将来「全收集」判定（`medals == 该星球套数`）。

**新表 `flower_exchanges`（可选但建议）** —— 兑换流水

```sql
CREATE TABLE flower_exchanges (
  id UUID PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES users(id),
  from_kind VARCHAR(16) NOT NULL,   -- 'flower' | 'star'
  to_kind   VARCHAR(16) NOT NULL,   -- 'star' | 'medal'
  set_no INT,
  knowledge_point_id UUID,
  amount INT NOT NULL DEFAULT 1,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

用途：**「今日星」的口径靠它**（当天 `to_kind='star'` 的 amount 之和），否则无法区分"今天兑的"和"以前兑的"。

**幂等与并发**：兑换接口必须带 `idempotency_key`，与前两版一致（规格 4.3 的既有约定）。
