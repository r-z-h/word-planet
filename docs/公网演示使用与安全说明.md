# Word Planet 公网演示 · 使用与安全说明（方案②：Cloudflare 临时隧道 + 口令门）

> 目的：把本机 `http://localhost:5173` 临时发布到公网，给家人/朋友演示。**只用于演示，不是生产部署。**
> 相关文件：`tools/tunnel.ps1`（启动脚本）、`tools/auth-proxy.mjs`（口令门）、`tools/bin/cloudflared.exe`（隧道程序）。

---

## 1. 它怎么工作

```
浏览器 --HTTPS--> trycloudflare.com --隧道--> 127.0.0.1:8080 口令门 --HTTP--> 127.0.0.1:5173 (Vite 前端)
                  （公网临时地址）           （登录页+Cookie）      └-- /api 代理 --> 127.0.0.1:8000 (后端)
```

- **只有口令门 8080 暴露到公网**；后端 8000 与数据库始终只在本机，经 Vite 的 `/api` 代理访问。
- 口令门对未验证访客返回**自带登录页**（HTTP 401，但**不带 `WWW-Authenticate`，浏览器不会弹框**）；提交正确口令后下发 HMAC 签名 Cookie（`wp_gate`，7 天），之后凭 Cookie 放行。
  输错只在页内提示，不会触发系统级凭据缓存（避免手机端整页空白），也不会与前端自身的 `Authorization: Bearer` 抢占请求头。
- cloudflared 与 Cloudflare 边缘是**出站连接**，路由器不需要开端口。

## 2. 前提

1. 开发栈已在跑：`.\dev.ps1 start`（前端 5173、后端 8000、PostgreSQL）。
2. `tools\bin\cloudflared.exe` 存在（**仓库不提交该二进制**；首次先运行 `.\tools\get-cloudflared.ps1` 自动下载，或从 Cloudflare 官方 release 手动下载 `cloudflared-windows-amd64.exe` 放到 `tools\bin\`）。
3. 首次运行会在 `node` 所在 PATH 中启动口令门（本机为 `C:\Program Files\nodejs\node.exe`）。

## 3. 命令（在项目根目录）

| 命令 | 作用 |
|---|---|
| `.\tools\tunnel.ps1 start` | 启动口令门 + 隧道，打印 **公网 URL / 用户名 / 密码** |
| `.\tools\tunnel.ps1 status` | 查看前端/后端/口令门/cloudflared 状态、当前 URL、登录口令 |
| `.\tools\tunnel.ps1 url` | 只输出当前公网 URL（供脚本读取；未运行则退出码 1） |
| `.\tools\tunnel.ps1 stop` | 停止口令门 + 隧道（**开发栈不动**） |
| `.\tools\tunnel.ps1 restart` | 等价 stop + start（**公网 URL 会变**） |

> `.ps1` 在本机没有文件关联，请用 `pwsh -File .\tools\tunnel.ps1 start`，或在 PowerShell 里执行。

## 4. 一次演示流程

1. `.\dev.ps1 start` 启动开发栈。
2. `.\tools\tunnel.ps1 start`，记下三样东西：**PUBLIC URL、USERNAME、PASSWORD**。
3. 把「链接 + 用户名 + 密码」一起发给对方；对方打开链接先看到**口令登录页**，输入正确账号密码进入（输错页内提示重试）。
   - 若对方只想随便试试，可在登录页点「**游客体验（无需注册）**」——每个模块各 3 题，不保存进度、不记错题（跟读模块不开放）。
4. 演示结束执行 `.\tools\tunnel.ps1 stop`，公网入口即关闭。

**每次 start 公网 URL 都会变**（临时隧道特性），别把旧链接当成固定地址。

## 5. 落盘文件与日志（均已 git-ignored）

| 路径 | 内容 | 说明 |
|---|---|---|
| `.run\tunnel-credentials.json` | `user` / `pass` / `createdAt` | **明文口令**，删除即轮换 |
| `.run\tunnel-gate.pid.json` | 口令门 `{pid, startedAt, port}` | 用于精确停止、防 PID 复用 |
| `.run\tunnel-cloudflared.pid.json` | cloudflared `{pid, startedAt, metricsPort}` | 同上 |
| `.run\tunnel-state.json` | 最近一次 start 的 `publicUrl` 等 | status 对照用 |
| `.run\tunnel-url.txt` | 纯文本当前 URL | 方便外部脚本读取 |
| `.logs\cf.err.log` | cloudflared 日志（含 URL） | 每次 start 轮换为 `.prev.log` |
| `.logs\auth-proxy.*.log` | 口令门日志 | 排查启动失败看 `auth-proxy.err.log` |

**公网 URL 解析优先级**：先读 cloudflared 自身 metrics（`http://127.0.0.1:20242/metrics` 的 `userHostname`，永远对应当前进程），读不到才退回解析 `cf.err.log`。这样旧日志残留也不会误报上一个隧道地址。

## 6. 安全要点（务必看）

1. **口令是唯一防线。** 口令门用「自带登录页 + 签名 Cookie」（兼容 Basic 供脚本）；请只把账号密码发给信任的人，演示完 `stop`。
2. **绝不要用 `--url http://127.0.0.1:5173` 直连启动 cloudflared。** 那会绕过口令门，把前端裸奔到公网（本机曾出现此类遗留隧道，已清理）。本脚本固定指向 `127.0.0.1:8080`。
3. **只暴露 8080。** 不要给 8000（后端）或 PostgreSQL 建隧道；后端仅经 Vite 代理。
4. **临时隧道无 SLA。** Cloudflare Quick Tunnel 不保证可用性、无固定域名，仅适合短期演示；正式长期使用需注册命名隧道。
5. **口令轮换**：`stop` 后删除 `.run\tunnel-credentials.json`，再 `start` 会生成新口令（旧链接即使泄漏也需口令）。
6. **本模式 Web 推送不可用**（VAPID/Push 依赖的地址与 HTTPS 在此模式下不可靠）。
7. **手机请用公网链接（HTTPS）**，不要用自签证书的 `https://<局域网IP>:5174`。
8. **日志/`.run` 含明文口令**：不要提交仓库、不要截图外发。它们虽在 `.gitignore` 中，仍可能被同步工具带走。
9. **养成收尾习惯**：演示结束 `stop`，避免口令门与隧道长期开着。

### 检查有没有「未授权隧道」

- `.\tools\tunnel.ps1 status` 会告警「非本脚本的 cloudflared」（通过命令行/指标端口识别）。
- 遗留直连隧道常用指标端口 **20241**；本脚本用 **20242**。
- 手工排查：
  ```powershell
  netstat -ano | findstr LISTENING | findstr ":20241 :20242"
  Get-Process cloudflared | Select-Object Id,StartTime
  ```
  确认是遗留进程后（可能需管理员权限）：
  ```powershell
  taskkill /F /PID <pid>
  ```
  > 提权进程（`Access denied`）需在「以管理员身份运行」的终端执行。

## 7. 故障排查

| 现象 | 处理 |
|---|---|
| `前端 5173 没在运行` | 先 `.\dev.ps1 start` |
| `口令门启动失败` | 看 `.logs\auth-proxy.err.log`；常见是 8080 被占或 node 路径问题 |
| 一直拿不到 URL | 看 `.logs\cf.err.log` 末尾；确认能出站访问 Cloudflare（企业网/防火墙可能拦 QUIC，本脚本已用 `--protocol http2`） |
| 自检显示「无法自检」 | 本机 curl 出站/DNS 受限时的正常提示；用浏览器或手机实际打开 URL 确认 |
| 访问返回 401 | 正常：说明口令门生效，输入正确的用户名/密码即可 |
| 旧链接打不开 | 临时隧道重启后 URL 已更换，重新 `status` 取新地址 |
| 页面**空白、只剩标题**（浏览器标签显示项目名） | 基本是前端 Vite 依赖预构建缓存坏了（F12 控制台见 `504 Outdated Optimize Dep`）。删 `frontend\node_modules\.vite*` 后重启前端。电脑 5173 与手机 5174 两个 dev 实例已分别用 `.vite-desktop` / `.vite-mobile` 缓存，勿再共用同一 `.vite`。 |
| Cloudflare `Error 1033` | 隧道掉了（本机出网/网络瞬断）。等 1–2 分钟 cloudflared 会自动重连，刷新即可；长时间不恢复再 `.\tools\tunnel.ps1 restart`（会换新地址）。 |
| `state` 与当前 URL 不一致 | 以 metrics 显示的为准；`restart` 可刷新 |

## 8. 本次完善（脚本 v2.0）

- 凭证/状态改为 **原子写入** `.run\*.json`，记录 pid + 启动时间，防 PID 复用误杀。
- PID 文件与端口双重兜底停止；`stop` 只清 pid/state，**保留口令**。
- 公网 URL 改为 **metrics 优先、日志兜底**，修复「旧日志导致显示上一次隧道地址」的问题。
- 每次 start **轮换日志**，新增公网侧 `401` 自检（网络受限时降级为提示）。
- 新增 `url` / `restart` 子命令；`status` 会告警可疑的第三方 cloudflared。

## 9. 2026-10-31 修复记录

### 9.1 登录后反复弹口令框
- **现象**：输对演示口令后进入应用登录页，输对应用账号密码后又弹一次口令框，如此循环。
- **根因**：前端每个接口请求都带 `Authorization: Bearer <token>`（`frontend/src/api/http.js`），把口令门的 `Authorization: Basic` 覆盖掉；口令门返回 401 + `WWW-Authenticate`，浏览器再弹框 —— 死循环。
- **修复**：口令门不再依赖 `Authorization` 头认证，改为「**登录页 + HMAC 签名 Cookie（`wp_gate`）**」；转发前剥掉任何 Basic 头，应用 Bearer 原样透传。

### 9.2 手机输错口令后整页空白（只剩标题）
- **现象**：手机（尤其微信内置浏览器）输错口令后整页空白、只剩标题，重开浏览器也不恢复。
- **根因**：浏览器原生 HTTP Basic 弹框在部分手机 webview 上有缺陷——输错后把错误凭据记进系统，之后只拿到缓存的 `index.html`（标题在）却取不到 `/src/main.js`（401），于是永远空白。
- **修复**：彻底去掉浏览器原生 Basic 弹框，改为**口令门自带的登录页**（见 §1）；未验证一律返回 401 HTML 登录页且**不带 `WWW-Authenticate`**，输错只在页内提示，不产生系统凭据缓存。服务端签名 Cookie 不受手机缓存影响。

### 9.3 验证
- 匿名访问公网 → 401 HTML 登录页（无 `WWW-Authenticate`）；
- 输入正确口令 → 302 + 下发 `wp_gate`，随后 `/` 与 `/src/main.js` 均 200；
- 输入错误口令 → 401 页内提示「账号或密码错误」；
- 经口令门 `POST /api/login` 拿 token 后，带 `Bearer + Cookie` 请求 `/api/me` 返回 200。
- Cookie 值由口令派生，**改口令即令旧 Cookie 失效**；`stop` 再 `start` 不影响 `wp_gate`。
