# 系统问答助手（Help Bot）· 知识源清单与架构草图

> 状态：**设计稿，未动代码**。
> 目标读者：接手实现的会话/开发者。先读本文件 + `AGENTS.md` + `需求说明书.md` + `Agent实现说明书.md`。
> 定位：**不是英语讲题 AI**，而是回答"这个系统怎么用/怎么解锁/规则是什么/我当前什么状态"的站内问答。
> 核心原则：**凡涉及数字、阈值、状态，一律来自代码常量或数据库，禁止 LLM 凭空生成。**

---

## 0. 实施顺序（已拍板 2026-11-10）

- **先做 A 层（Phase A）**：结构化查询 + 模板答案，**零 LLM、零向量库**。先把能确定性回答的高频问题跑通并上线。
- **B 层后做（Phase B）**：需要语义检索（FAQ 语义召回 / 意图兜底）时，**届时再建向量库**——先"普通列 + 内存余弦"，条目上千再迁 pgvector；A 层始终作为兜底保留。
- **B 层的 LLM、向量库、复杂语音能力都不在 Phase A 范围。** Phase A 交付即可上线，不触碰"不调 LLM"的需求红线；语音输入可作为 A 层的"输入附加项"，在文本问答跑通后再接。
- **多轮对话**：Phase A 用"槽位/话题跟踪"实现（零 LLM，见 §6.5）；自由省略、换话题、纠错等留给 Phase B。
- **入口形态**：**所有页面常驻**角落**卡通人物形象**（先占位图，可最小化），点击打开对话面板（多轮聊天），非简单「?」按钮。

## 1. 目标与范围

- **回答**：关于本站的用法问题，例如"我怎么才能做能力测试""某个徽章怎么解锁""花/星/徽记怎么换""我今天任务完成了没"。
- **不回答**：英语知识点答疑（由答题解析/错题本承担）、开放闲聊、与本站无关的问题。
- **正确性优先**：宁可说"我不确定，请看 XX 页面"，也不能编一个像样的错答案。
- **可个性化**：能结合当前登录用户的真实进度回答（"你还差 2 枚徽记"），这是纯文档 RAG 做不到的。
- **可降级**：A 层靠"修 + 测试 + 异常兜底"保正确（查询异常降级为友好提示，不 500）；`HELP_LLM_ENABLED` 总开关**只针对 B 层 LLM**——A 层是确定性代码，不需要 kill switch。

## 2. 分层架构

> **对用户只有一个入口**：一个输入框 / 一个接口 `POST /api/help/ask`。
> A 层、B 层只是**服务端内部**的路由分支，由系统按问题自动判断，用户完全无感——不需要用户自己选。

```
用户提问（打字，或语音→转文字）
   │
   ▼
① 意图识别（关键词/正则优先，模型兜底）
   │
   ├─ A 规则/状态类 ──► 调「查询工具」（服务函数 / 现有接口 / 常量）
   │                     └► 模板组装答案（数字全部来自返回值） ──► [可选] LLM 仅润色
   │
   ├─ B 解释/政策类 ──► 检索人工 FAQ 库（关键词→向量）
   │                     ├ 命中 ─► 附出处回答
   │                     └ 未命中 ─► "我不确定…" + 相关页面链接
   │
   └─ 其它 ──────────► 礼貌拒答 + 引导到对应页面
```

**关键设计**：
- **A 层不接 LLM 也能跑**，因此可以先上线一个"零 LLM、零合规风险"的确定性帮助机器人。
- **B 层才可能需要 LLM**（把 FAQ 命中内容组织成人话）。B 层也可以只用关键词拼装，完全不用 LLM。
- 无论哪层，答案里出现的数字必须来自 ② 的查询结果或常量，**不允许模型自己算/自己填**。

## 4. 星球与解锁门槛速查（来自 `knowledge_points` 表，以库为准）

| 等级 | 星球 | 题型 | 计入门槛 | 门槛类型 | 门槛数量 | 产花 | 徽记 |
|---|---|---|---|---|---|---|---|
| L1 | 字母表 | letter | 是 | completion（15 题全对=完成） | — | ❌ | — |
| L1 | 基础问候词 | word | 是 | medals | 5 枚 | ✅ | 🥚 破壳蛋 |
| L2 | 常用单词 | word | 是 | medals | 3 枚 | ✅ | 🐻 小熊 |
| L2 | 简单拼写 | spelling | 是 | medals | 5 枚 | ✅ | ✍️ 铅笔 |
| L2 | 单词跟读 | pronunciation | 是 | medals | 7 枚 | ✅ | 🐦 小鸟 |
| L3 | 听力理解 | listening | **否** | — | — | ✅ | 🎧 耳机 |
| L3 | 拼写进阶 | spelling | 是 | medals | 0（L3 终点，不卡） | ✅ | 🔮 水晶球 |

- 解锁 L2 = **字母表"已完成"（15 题全对）+ 基础问候词 5 枚徽记**。
- 解锁 L3 = **常用单词 3 + 简单拼写 5 + 单词跟读 7**（各自单独凑够，不是合计）。
- L3 为终点，无下一级；听力理解**不参与任何解锁**。
- 这些数值直接来自 `knowledge_points.gate_mode / gate_required / produces_flowers / medal_name`，改库即生效，问答不要另存一份。

## 5. 问题 → 数据源 → 答案模板（主表）

### 5.1 A 层：规则 / 状态类（确定性，优先做）

> 数据源优先用**服务函数**（`level_gate` / `set_summary` / `rewards.*` / `award_badges` 相关计数），或**现有接口**（`/api/lesson/overview`、`/api/level-test/status`、`/api/reward/summary`、`/api/progress`、`/api/achievements` / `/api/report`）。答案里的数字一律来自返回值。

## 6. 需要新增的组件

### 6.1 后端
- `backend/app/services/help.py`：一组**只读查询函数**（供 A 层调用，也便于测试）：
  - `gate_status(user)` → 复用 `lesson.level_gate`
  - `badge_status(user)` → 读 `badges` + `achievements`，可算的算"还差多少"
  - `reward_summary(user, kp, set_no)` → 复用 `reward._summary`
  - `progress_summary(user)` → 复用 `/api/progress` 逻辑
  - `rule_constants()` → 从常量生成"3 花=1 星"等说明
- `backend/app/routers/help.py`：
  - `POST /api/help/ask`：`{ "question": str, "context": {...}? }` → `{ "answer": str, "mode": "rule"|"faq"|"refuse", "sources": [...], "context": {...}, "suggestions": [...] }`
  - `GET /api/help/faq?q=`：**可选辅助**，仅用于前端"常见问题快捷按钮"的推荐/搜索；它**不是**用户提问入口，用户提问统一走 `POST /api/help/ask`。
  - `WS /api/asr/stream?lang=zh_cn&token=`：**语音转文字**（复用讯飞 IAT 转发），语音提问用；详见 §6.4。它只负责把话转成字，转完仍进 `POST /api/help/ask`。
- FAQ 存储（二选一，见 §10）：`faq` 表，或 `docs/faq/*.md` 约定格式。
- 日志表 `help_qa_log(id, question, mode, matched_rule/faq_id, answer, sources, model, latency_ms, created_at)`，**脱敏**。
- 开关：**A 层不设总开关**（确定性代码，靠"修 + 测试 + 异常兜底"保正确）；`HELP_LLM_ENABLED`（B 层是否启用 LLM），写 `.env`。

### 6.2 前端（入口 = 角落卡通形象 + 对话面板）
- **入口**：**所有页面常驻**一个**卡通人物形象**（角落，不挡正文，可最小化成小头像），点击打开**对话面板**（不是简单的「?」按钮）。
- 面板：消息气泡对话流 + 输入框 + 🎤 语音按钮 + 推荐问题快捷按钮 + 答案区（带"来源"链接）。
- **多轮连续对话**：可追问（如"那我还差几枚？"），需记住上文的实体/意图（见 §6.5）。
- 输入框支持语音提问（语音→文字→同一接口，详见 §6.4）；可选 🔊 朗读答案（`SpeechSynthesis` `zh-CN`）。
- 卡通形象素材：**先用占位**（现成 emoji/图片），界面与逻辑先跑通，后期再换正式形象；预留 idle / 思考中 / 说话 状态。

### 6.3 意图路由
- **规则优先**：一批关键词/正则映射到 A 层查询（如含"能力测试/解锁/还差"→ A1；含"花/星/徽记/兑换"→ A5；含"徽章"→ A4）。
- 命中即走确定性路径；未命中再查 FAQ；再未命中 → 拒答 + 引导。
- 可选：用小型模型做意图分类兜底，但**分类结果只决定走哪条路，不直接产出数字**。

### 6.4 语音输入（对话接语音）

> **一句话：语音只是"输入法"。** 用户说话 → 转成文字 → 走同一个 `POST /api/help/ask`。A/B 路由、答案与打字完全一致，**不新增第二个问答入口**。

**技术路线（复用现有能力，不重造）**
- 项目已有讯飞 **IAT 实时转写**：`backend/app/services/iflytek.py:190 iat_auth_url()`；且 `backend/app/routers/pronunciation.py:340` 的 `WS /api/pronunciation/stream` 已实现"浏览器音频分片 → 讯飞 IAT → 回推 interim/final 文本"。
- 建议抽成**通用 ASR 通道**：新增 `WS /api/asr/stream?lang=zh_cn&token=`（复用 `_relay_iflytek`，把 `language` 改成 `zh_cn`），供帮助对话使用；不要把问答语义挂在 `/pronunciation/*` 下。
- 前端 `frontend/src/components/game/MicRead.vue` 已有 AudioWorklet 采 PCM + 推流，抽成 `useStreamingAsr` 组合式函数，`HelpDialog.vue` 的 🎤 按钮直接复用。

**降级顺序（必须有，不能因语音不可用就卡住）**
1. 讯飞已配置 → 流式识别（边说边出字）；
2. 未配置讯飞、但浏览器有 `SpeechRecognition` → 用浏览器原生（`zh-CN`）兜底；
3. 两者都没有 → 隐藏 🎤，只留打字，提示"当前浏览器不支持语音输入"。

**硬条件**
- `getUserMedia` 需要**安全上下文**：`http://localhost` 视为安全可用；手机必须走 `https://<局域网IP>:5274`（项目已有自签证书）。`http://` + 局域网 IP 下麦克风不可用。
- 语音请求同样受登录鉴权（WS 用 `?token=` 传 JWT，与现有 `/pronunciation/stream` 一致）。
- 交互用"点一下开始 / 再点一下结束"即可，不做唤醒词、不做全双工对话（控制复杂度）。
- 可选：答案用 `SpeechSynthesis`（`zh-CN`）朗读。

### 6.5 多轮对话与上下文（Phase A 也做，但零 LLM）

- **上下文载体**：不新建会话表。前端保存 `messages[]` + `context`（如 `last_intent`、`last_kp_id`、`last_badge_code`），每次请求带上，服务端返回更新后的 `context`。**服务端无状态**，简单、可扩展。
- **Phase A 的"多轮"= 槽位/话题跟踪（确定性）**：把"那我还差几枚""这个徽章呢"解析成"沿用上一个实体"的追问——用 `context` 里的 `last_*` 补全，仍走 A 层的"查库 + 模板"。**不依赖 LLM。**
- **边界**：槽位跟踪能覆盖"指代上一个实体"的追问；更自由的省略句、换话题、纠错，等 Phase B 引入 LLM 再做。Phase A 遇到消解不了的追问，就回"你想问哪个星球/徽章？"并给候选按钮。
- **请求/响应**：加 `context` 字段；响应可带 `suggestions`（下一句可点的候选），把多轮引导做得不靠模型猜。

## 8. 五个必须避开的坑

1. **文档漂移**：数字/阈值绝不写死进 FAQ 文本，一律走 A 层实时取数。改代码即生效。
2. **`SETS_REQUIRED=3` ≠ 解锁门槛**：解锁看各星球 `gate_required`/`completion`；别把"3 套"当通用答案。
3. **命名混淆**：`星球徽记` / `成就徽章` / `花·星·徽记` 三套概念必须区分，否则一定误导。
4. **置信错误**：模型把"可能/一般"说成"一定"；要求"未取到数据就说不确定"。
5. **失控越界**：只答本站相关问题，其余拒答（也控成本、控合规）。

## 9. 验收标准

- 造 **30–50 条真实问题**（见 §11）做回归；A 层问题答案里的数字与数据库/常量**逐一比对一致**。

- 关掉 `HELP_LLM_ENABLED`（B 层）后应退回 A 层、不报错；A 层无总开关，任何查询异常都降级为友好提示、不返回 500。
- A 层答案 P95 < 200ms；若引入 LLM，B 层 P95 < 3s。
- 每条答案带可点击"来源"（A 层给页面/接口，B 层给文档章节）。
- **语音提问**：说一句中文问题能正确转写、并得到与打字**完全一致**的答案；麦克风不可用或讯飞未配置时，优雅降级到打字，不报错、不阻塞。

## 14. Phase B 重构为**独立 RAG 模块**（2026-11-12，取代 §12/§13 的 FAQ 方案）

> 之前的 "18 条固定问答对 + 检索一条" 被判定为"LLM 没活干"，现已改为**独立模块 + 专用知识库 + 文档型 RAG（LLM 多片段综合）**。

### 目录（与主项目解耦）
- **知识库（内容层，独立）**：`rag_kb/articles/*.md` —— 10 篇用户向帮助文章（按标题/段落组织，便于切块）；`rag_kb/README.md` 说明维护方式。**不含任何工程文档/实现细节**。
- **引擎（代码层，独立包）**：`backend/rag_engine/`
  - `chunker.py` 切块（按 `##` 分节，段落到 ~450 字）
  - `embedder.py` 本地 bge（离线）
  - `engine.py` 建索引 + 混合检索 + 组装消息/引用 + 抽取兜底
  - `__init__.py` 暴露 `query/warmup/build_index`
  - `build_index.py`：`python -m rag_engine.build_index`（生成 `rag_kb/index.json`，已 gitignore）
  - **不 import app / 数据库 / 说明书**；LLM 由调用方以 `chat(messages)` 注入，引擎不绑定具体供应商。

### 检索 / 生成
- 切块：43 个片段；向量=bge 512 维。
- 检索：**混合分 = 0.8×余弦 + 0.2×关键词(中文二元组覆盖率)**，top-5，阈值 **0.40**（真实命中≥0.47，无关"天气"0.378 被挡）。
- 生成：把 top-5 片段交给 DeepSeek，**综合多条 + 用 [n] 标注引用**；出处只列**真正被引用**的片段；LLM 失败/关闭 → 退回最相关片段原文（抽取式）。
- A 层（数字/状态，查库）保持不变，B 层替换为该独立引擎。
